# DataSophon packaging and lifecycle reuse

Research date: **2026-11-02**. For [Research DataSophon component packaging and lifecycle reuse](https://github.com/jayyu-asl/OpenDataHub/issues/22). Public source/document inspection only; no implementation, deployment, benchmark, operational test or certification.

## 1. Answer, authority and provenance

**Use DataSophon as a bounded design reference, not an adopted controller or source of production recipes.** Its historical descriptor/template/role-strategy separation and local archive distribution are useful. The inspected execution and trust paths do not justify replacing the recorded Go/SQL/bbolt/gRPC-mTLS/systemd boundaries. This is a fit judgment, not a measured cost advantage.

Build on the accepted [Management foundations for parcel-like offline component delivery](https://github.com/jayyu-asl/OpenDataHub/blob/d93b8a921dfd05ee2a26f58afcac7df728a06be9/docs/research/management-foundation-parcel-evaluation.md) and [Go-native durable lifecycle orchestration reference patterns](https://github.com/jayyu-asl/OpenDataHub/blob/b7ba20c932c70a8a2b8e77ab86aab9e22b8b48f8/docs/research/go-lifecycle-orchestration-patterns.md), rather than repeat their platform survey. Authority remains with [Choose the implementation stack and repository organization](https://github.com/jayyu-asl/OpenDataHub/issues/11), including its latest [Choose the implementation stack and repository organization — operation implementation direction and release tooling checkpoint](https://github.com/jayyu-asl/OpenDataHub/issues/11#issuecomment-6575978228). Fixed workflow/security/support/licensing decisions are P1–P4 below. The baseline remains a modular Go controller/optional workers, Go SSH then agent-initiated gRPC/mTLS, PostgreSQL **and** MySQL (admitted customer DB/default managed PostgreSQL), bbolt agent records, systemd, controller-hosted React/TypeScript, declarative definitions/typed Go Adapters, signed CI archives/exact distribution pins and FreeIPA/OpenBao companion roles. This report changes none of them.

**Current authoritative implementation remains inaccessible/unverified.** The first-party website repository `datasophon/datasophon-website`, inspected at `0075d38b3f44c349847214e91257e74aaa538329`, points to `datasophon/datasophon` in contribution/configuration links and `datavane/datasophon` in its home-page source. No inaccessible implementation or release assets were read. These observations establish neither abandonment nor a canonical successor. [W1–W3]

## 2. Concrete mechanisms and fit

The snapshot is Java 8/Maven: Spring Boot `2.6.1`, MyBatis-Plus `3.2.0`, MySQL Connector/J `8.0.28`; a Java API/controller embeds master orchestration actors, while **worker means the privileged host agent**, not an independent central execution-worker tier. UI is Vue `2.6.11`/Ant Design Vue, not React. MySQL configuration/migrations are concrete; PostgreSQL management support was not established. Akka is embedded remoting, not a separate broker. No mandatory Redis/Kafka control substrate was found in the inspected launch/configuration paths. [S1–S3]

| Reusable mechanism | Snapshot implementation | Fit / gap against fixed OpenDataHub contracts |
| --- | --- | --- |
| Component declarations | `service_ddl.json`: version, archive/directory, dependencies, roles/cardinality/runAs, runners, parameters and config generators; loader persists metadata and refreshes changed definitions | Good vocabulary for schema-validated declarations; not a signed immutable distribution pin or runtime dependency solver [S4] |
| Templates plus native strategies | FreeMarker XML/properties/custom files, package-local extra template loading; compiled role-name strategy registry | Useful declarative/typed-Adapter split. Generic additions can be metadata; special semantics require Java changes/rebuild, not arbitrary hot plugins [S5] |
| Archive delivery | Controller package directory, architecture-aware package choice, worker cache/download/extract | Useful local/offline distribution seam; integrity, staging and activation need replacement, not copying [S6] |
| Ordering and results | Dependency DAG, reverse DAG for stops, sorted master roles before worker/client dispatch; persisted command/host/role rows | Useful plan/progress hierarchy; memory execution state and boolean outcomes do not supply durable uncertain-effect reconciliation [S7–S8] |
| Configuration history | Role-group configuration versions and restart-required flags | Reference for desired revisions; not demonstrated observation of effective files/running versions or controlled drift adoption/restoration [S9] |
| Host bootstrap | SSH upload/check/extract/JDK/start chain; worker announces itself to controller | Comparable two-phase topology; incompatible trust, privilege and transport defaults must not be inherited [S10–S11] |

**Packaging detail:** API/worker Maven assemblies produce management tarballs with jars, scripts, metadata/templates, UI/resources and collectors. Component archives are separately prepared: DolphinScheduler instructions rename an upstream binary tree, add JMX, alter status exit behavior, add MySQL jars and create tar/MD5 files. This is actual repackaging knowledge, not a complete pinned source-build factory or dependency BOM. Flink “upgrade” instructions edit metadata/environment paths and restart management processes; they do not prove native job/state migration or rollback. [S2, S12]

`InstallServiceHandler` checks an **existing cached** package against supplied MD5, downloads via **HTTP** when needed, then extracts; no post-download verification appears in that path. On the controller host the download/check decision is skipped. Existing destination-directory presence returns success without proving complete extraction or version identity. Configuration, logs and some state remain within component trees. The controller's install chain immediately proceeds **install → configure → start**, so installation is not separately approved activation; no atomic selection, immutable signatures, running-version validation or safe retained-version rollback is established. [S6, S8]

**Offline boundary:** local archives and bundled jars help, but bootstrap hard-codes JDK `8u333` archive names and uses SysV/chkconfig/service scripts, not the selected systemd contract. Closure also includes OS/native packages, sudo/accounts, JDBC, Hadoop clients, component runtimes, trust and recovery materials. `checkServiceDependency` additionally requires Prometheus, Alertmanager and Grafana even for unrelated installs. Do not equate docs' “Java only” design goal with dependency-complete offline execution. [S10, S13, W4]

## 3. Source traces: stock, extensions and lifecycle limits

**HDFS → YARN:** DDP-1.2.1 contains HDFS/YARN `3.3.3` declarations sharing `hadoop-3.3.3`; HDFS depends on ZooKeeper, YARN on HDFS. Roles include JournalNode/NameNode/DataNode/ZKFC/client and RM/NM/history/client, with service accounts and native control scripts. Strategies supply keytab/plugin/start handling, not merely names. Critically, new-install primary NameNode logic deletes `/data/dfs/nn/current` and formats; standby uses `-bootstrapStandby`. This is direct counterevidence to treating install as Service Adoption or safe retry. Native HA configuration is not management-controller fencing. [S14]

**Hive/HMS → Tez:** Hive `3.1.0` declares only HDFS dependency, HS2/HMS/client roles and MySQL configuration. `HiveServer2HandlerStrategy` initializes MySQL schema on initial non-slave install, creates HDFS warehouse/temp directories, enables optional Ranger/Kerberos, and links Tez configuration **if** `/opt/datasophon/tez` exists. Hive's engine selector defaults to `mr`, although `tez` is selectable. A registered `TezServerHandlerStrategy` reads `tez.lib.uris`, creates/chowns an HDFS directory and uploads `share/tez.tar.gz`; the final result comes from generic start/status rather than requiring every upload command to succeed. **Neither bundled DDP-1.2.0 nor DDP-1.2.1 contains a TEZ descriptor.** This is partial implementation/extension evidence, not a stock resolved Hive-on-Tez path, distributed SQL smoke, ACID compactor validation or offline worker closure. [S15–S16]

**Heterogeneous stock example — Doris:** DDP-1.2.1 declares Doris **`1.2.6`**, FE/FEObserver/BE with local metadata/storage paths; no role-level `runAs` appears. FE helper startup and BE startup send asynchronous membership-add commands to controller `MasterNodeProcessingActor`, which retries failed SQL registration up to three times. Worker startup success can precede membership success: an illustrative multi-effect boundary. This is classic integrated FE/BE, **not** disaggregated MS/FDB/Recycler/native-vault management or coordinated recovery. None of the agreed Doris transport, writer/Recycler fencing or compatible FE/FDB/files recovery obligations is discharged. [S17]

The bundled tree also has Trino, DolphinScheduler, Kafka, Flink/Spark clients, Ranger, Kerberos and an Iceberg client declaration. These are bounded stock definitions, not proof of end-to-end integrations or the full OpenDataHub catalog. ClickHouse/MinIO/OpenLDAP integration documents are **extension recipes**, not stock adapters; ClickHouse explicitly requires adding a compiled strategy. No Service Adoption/Service Offboarding, native upgrade/recovery acceptance or general backup/DR contract was established by the traced install/start/change paths. [S18]

## 4. Persistence, ambiguity and ownership

Command generation stores service/host/role records; statuses include WAIT/RUNNING/SUCCESS/FAILED/CANCEL with progress/output. But `DAGBuildActor` allocates active/error/ready/complete maps in memory and passes them in messages. The traced actors are `UntypedActor`, not persistent workflow actors. Worker configuration naming “at-least-once-delivery” and `akka-persistence` dependencies do not prove use: its configured journal is **in-memory**. No durable agent receipt/result-outbox protocol was established. [S7–S8, S11]

Controller install/config/start handlers use `ask`/`Await` with 180-second timeouts and return a default unsuccessful `ExecResult` on exceptions. Result handling converts that boolean to FAILED: it cannot distinguish definite failure from **effect committed, reply lost**. Reissuing install after lost NameNode-format or HMS-schema completion can repeat hazardous initialization before a role is recorded. Generic PID/status prechecks help process convergence, not native transaction reconciliation. [S6, S8, S14–S15]

Cancellation is particularly bounded: `cancelCommand` is empty although its API returns success; failure propagation marks downstream DB records CANCEL and uses an in-memory cancellation map checked by master-role iteration. This is not acknowledged remote interruption or reversal of native work. Worker registration can auto-start roles selected from stored stopped state; it is not replay of durable approved operation history. No restart recovery of the execution DAG, target fencing tokens, cross-controller leases or explicit UNKNOWN result model was established in these paths. [S7–S8, S19]

Configuration MD5s/revisions detect changes to stored declarations, and status actors probe selected services. They do not prove external-file drift reconciliation, ownership transfer or stale-controller exclusion. Preserve the accepted Go report's intent/delivery/observation separation; do not port actor messages as an operation engine. [S4, S9, S19]

## 5. Trust, licensing and maintenance boundaries

- **SSH:** `MinaUtils` uses MINA SSHD `2.9.2` default client without an explicit trusted-host verifier. That version's `ClientBuilder` defaults to **AcceptAllServerKeyVerifier**. Its key helper also generates a new RSA pair instead of visibly decoding the supplied private key; working authentication is not established by this inspection. Bootstrap writes system paths/sysctl/SysV configuration without the required capability-checked sudo contract. [S10, L3]
- **Agent/secrets:** actual configs/addresses use `akka.tcp` on ports 2551/2552, not mTLS enrollment. Keytab acquisition uses HTTP; its endpoint is excluded from the login interceptor and the traced controller/service adds no peer authentication. Keytab directories are recursively group-writable; KDC commands include/log the administrative password. Login/token and cluster-manager checks exist, but do not establish complete scope, denial audit or Platform Identity mapping. [S11, S20]
- **Audit:** command rows and application logs exist; no durable critical-audit-before-success/refusal contract was established. The above paths require redesign, not a private-network exception. [S8, S20]

The snapshot's root **LICENSE is Apache-2.0**, with author/third-party attribution in NOTICE, not blanket clearance of its payloads. Actual declared actor/remoting artifacts are `com.typesafe.akka:akka-{actor,remote,persistence,slf4j}_2.11` **`2.4.20`**; service/worker POMs instantiate these dependencies. That version's upstream license and published remote-artifact POM say **Apache-2.0**: applying a later Akka license label retroactively would be wrong. Conversely, upgrading to another release requires fresh review; permissive history does not approve future artifacts. Connector/J `8.0.28` POM declares **GPLv2 with FOSS exception**; its exact distribution terms/combination need review. JDK filenames alone establish neither vendor identity nor redistribution rights. [S1–S3, L1–L4]

Learning mechanisms differs from copying/porting templates, scripts or Java. Any later copy requires immutable provenance, file/dependency notices, change attribution, source/build-material fulfillment and human artifact/activity review; no source was copied into OpenDataHub. A separate network process is not a legal safe harbor. Porting would own native-version/path assumptions, state migrations, account/security fixes, schema compatibility and heterogeneous recovery; adopting the product additionally inherits JVM/Scala/Akka/UI dependencies and a presently unverified maintenance channel. No staffing or lifecycle-cost measurement supports a cheaper claim.

## 6. Recommendation, counterevidence and unresolved facts

**Keep the fixed stack; reuse ideas, not this runtime.** Borrow role/cardinality/config-generator vocabulary, package/definition separation, explicit dependency ordering and per-host progress presentation. Re-express them through validated definitions/typed Go Adapters and signed pinned CI archives, without importing unsafe install semantics or a general workflow DSL.

Strongest counterevidence is implemented multi-service UI/configuration/monitoring/bootstrap machinery plus real native strategies: first-party implementation forfeits substantial ready-made work. Source cannot prove that rebuilding it is cheaper. Reconsider only through an explicit human decision if an admissible maintained release demonstrates required delivery, trust, dual-SQL and restart/ambiguous-effect contracts with localized changes.

**Smallest missing evidence:** an owner-confirmed current canonical repository/release pointer, or immutable release-source archive plus tag-to-commit/checksum provenance and matching dependency/license inventory. It must establish whether the preserved tree corresponds to an actual release and what changed. Without that, current coverage/security/support conclusions remain blocked; the historical mechanism comparison remains legitimate but cannot certify today's upstream. No prototype or operational validation is authorized by this report.

Validation here covers report-only diff, word limit, whitespace, named links, pinned source-path existence and material content inspection. It is not software testing, legal clearance or operational certification.
