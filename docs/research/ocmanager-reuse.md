# OCManager controller-agent and lifecycle reuse

Research date: **2026-11-02**. For [Research OCManager controller-agent and lifecycle reuse](https://github.com/jayyu-asl/OpenDataHub/issues/21). Public source inspection only: no implementation, build, deployment, operational test, benchmark or certification.

## Decision boundary and provenance

**Recommendation: reference mechanisms, not adoption of OCManager as OpenDataHub's management foundation or an imported agent/runtime.** Its private-RPM publication workers are stronger learning material than its generic command channel. Neither establishes the complete required data-service lifecycle contract. No evidence here warrants automatically replacing a recorded choice; reconsideration remains human-owned.

This extends the immutable [Management foundations for parcel-like offline component delivery](https://github.com/jayyu-asl/OpenDataHub/blob/d93b8a921dfd05ee2a26f58afcac7df728a06be9/docs/research/management-foundation-parcel-evaluation.md) and [Go-native durable lifecycle orchestration reference patterns](https://github.com/jayyu-asl/OpenDataHub/blob/b7ba20c932c70a8a2b8e77ab86aab9e22b8b48f8/docs/research/go-lifecycle-orchestration-patterns.md), not their whole-platform surveys.

The full research issue/comments and live [Choose the implementation stack and repository organization](https://github.com/jayyu-asl/OpenDataHub/issues/11), including its latest additional-research request, were read. Preserve Go modular controller/workers/agent/core CLI; PostgreSQL **and** MySQL, customer DB or default self-managed PostgreSQL; Go SSH bootstrap then agent-initiated gRPC/mTLS; bbolt local records; systemd; controller-hosted React/TypeScript; typed Go Adapters/declarations; immutable CI archives/signed manifests and exact Platform Distribution pins; FreeIPA/OpenBao companion roles. Canonical management, security, licensing and support decisions remain fixed [P].

## Representative traces: implemented does not mean safe replay

### Generic artifact command and lost result

`OpsTasksPublish → PublishTask → DeployStructuredTaskImpl` derives an idempotency key and writes the task, then target rows, then launches dispatch in a goroutine. These are not one durable intent/payload/target transaction. Structured creation does not persist its action body in `ContentMD5`; the reconnect path rebuilds legacy command payloads from stored action/content. Thus persisted rows and an `OnAgentConnect` hook do not establish restartable structured dispatch [S4, S6].

`pushStructuredToAgents` pushes before `MarkTargetSent`. `pushOnceWithRetry` deliberately avoids retry on `context.DeadlineExceeded` because delivery may already have occurred; other errors get one delayed retry. This is useful explicit uncertainty awareness, but not a general proof that every other error means no delivery. Pending reconnect delivery is ordered by creation time; there is no verified cross-task dependency ordering [S6].

Agent `Router.dispatchRunArtifact → Runner.Execute` downloads with retry, checks MD5, unpacks and runs `sh run.sh`, then reports. The router permits concurrent executions and explicitly does not deduplicate task IDs. Shell execution inherits the agent identity; the supplied systemd unit has no `User=`, and installation requires root. Timeout/context cancellation sends process-group signals; that cannot retract an already committed database migration or submitted native job [A3, A4].

**Lost reply after native effect:** suppose `run.sh` commits a schema change, then its result is lost. Production `main.go` wires plain `runnerReporter`, which sends `CmdAck` through the socket; successful write is not durable controller acceptance. Gateway uses a bounded in-memory ACK queue and bounded forwarding retries, then logs/drops failures without returning a receipt to the agent. Task-manager's SENT sweeper marks TIMEOUT, not native failure. `MarkTargetAck` rejects terminal targets, so late results cannot simply repair timeout status [A4, S4, S7].

There is a tested `RetryingReporter`/JSON `ReportSpool` helper, but **no production construction/replay call** in this agent tree. Its claimed fsync guarantee also exceeds `Persist`'s actual write/rename calls: neither file nor directory is synced. Even wiring that helper would resend an available result, not recover a crash between native effect and result creation. Safe result resend is categorically different from rerunning a hazardous command. No exactly-once effect follows [A5].

Generic `CancelOpsTask` changes SQL statuses without sending an agent stop request. Agent connection-epoch cancellation can terminate local shell processes; it is not task-specific remote cancellation acknowledgment, nor proof that external work stopped [S6, A4].

### Private-RPM repository: stronger, narrower counterevidence

Do not generalize those generic-channel limits to every OCManager worker. `ClaimNextForNode` uses transactional candidate selection (`FOR UPDATE SKIP LOCKED`), a per-repository mutation lock, increasing fencing token and lease. Heartbeat/completion verify worker, node and ownership. `RemoteWorker` cancels on heartbeat failure and checks cancellation before commit; source tests exercise these branches [R1, R2].

Publication materializes a revision with RPM/source labels and SHA-256 checksums, generates `createrepo_c` metadata, optionally signs metadata, and makes the revision read-only. Remote commit is **prepare metadata → activate local current link → confirm metadata**. Matching prepare/confirmed requests have idempotent cases. This usefully separates staged material from advertised state [R2–R4].

However, activation's filesystem rename and controller SQL commit are not atomic together. `RemoteSyncExecutor.Activate` switches/verifies the link without a target-side fencing-token check; `commitRemoteOutcome` returns on lost confirm response. Expiry recovery releases ownership and requeues within its attempt budget. These paths do not establish native-state observation before every replay, durable node-side commit recovery, or prevention of every stale filesystem mutation. Study prepared-result identity and conditional acceptance, **not a claim that leases fence arbitrary service effects** [R1, R2, R4].

## Security, delivery and independent recovery

Enrollment requires an independently delivered CA. Agent TLS verifies the server through its CA pool; gateway permits certificate-less registration but restricts anonymous traffic, and validates supplied client certificates plus CRL during handshake. Asset admission checks UUID/IP/MAC, defaults to an explicit whitelist in shipped configuration, and server-side certificate generation returns both certificate and private key. A self-reported fingerprint is not independently authenticated host possession; no selected SSH known-host/enrollment contract was established by the inspected install path [S5, A2, A3].

There is meaningful security code: CA-key encryption uses PBKDF2/AES-GCM; API HMAC binds method/path/identity/time/nonce/body, strict mode fails closed without a secret, and task-manager authenticates an internal service token. HMAC replay memory is process-local. Repository authorization checks project ownership/global role. These are not evidence of the required Platform Identity, environment-scoped authorization and all-link encryption. Compose includes plaintext Kafka; `SECURITY.md` acknowledges shared initial administrator credentials and requires rotation. CRL handshake checks alone do not prove bounded revocation of existing sessions [S3, S5, S8, R1].

Critical-audit compatibility is also unproven: task publication logs an audit line; the manager permission filter launches browse-audit RPC asynchronously and ignores its outcome. Neither establishes durable-audit-before-success/refusal. CA encryption does not encrypt all SQL, result, configuration, log and backup material [S6, S8].

**Distribution distinction:** generic file-svc CAS uses MD5 and source/task labels; that is not signed provenance or exact binary-to-source/patch/notices mapping. The newer RPM subsystem does implement stronger SHA-256 manifests, immutable revision URLs, RPM GPG policies and optional metadata signatures—counterevidence to calling all OCManager distribution “MD5 only.” Signing policy can be disabled/audit-only; these RPM mechanisms are not the selected mandatory signed component-archive contract. Repository-current selection is not running-service activation or schema rollback [S9, R3, R4].

Agent packages and systemd can be installed independently; Compose supports an internal image mirror and persistent volumes. But documented bootstrap builds/downloads dependencies, and image tags are not digest pins. No complete disconnected bootstrap/replacement/recovery closure or consistent recovery of MySQL, SQLite stores, artifacts, CA/keys and pending operations was verified. No dependency on managed HDFS/Ozone/YARN is shown, yet independence alone is not a recovery procedure. OCAI/external inference remains an optional upstream integration, **not an OpenDataHub requirement or public runtime dependency** [S1–S3, A3].

## Licensing, maintenance and recommendation gates

Root `LICENSE` in **both** projects is GPLv2 text; OCManager `NOTICE` describes GPL version 2 and separately identifies MIT TDesign-derived portions. Crucially, inspected TMS task/store code, agent runner/spool and shared protocol files instead declare **GPL-3.0-or-later**, including an explicit v3-or-later grant in `frame.go`. Do not flatten this into “GPLv2 everywhere,” infer an applicable upgrade option from a license template, or treat frontend MIT as licensing the whole product. Obtain maintainer clarification of exact file/module grants before reuse [L1].

Checked dependency anchors: tRPC-Go `v1.0.3` is Apache-2.0 with a third-party inventory including MPL/BSD/MIT; go-sqlite3 `v1.14.44` driver is MIT; go-sql-driver/mysql `v1.7.1` is MPL-2.0; GORM `v1.25.5` is MIT [L2]. This is **not** an exhaustive transitive, embedded SQLite, npm or container license audit. Imports/copying/forks create different obligations from separately connecting to/distributing services. First-party Apache-2.0 cannot relabel GPL files or clear a combined work; process separation is not automatic legal shelter. Copyleft remains reviewable under fixed policy, not categorically forbidden. No upstream product code was copied.

Maintenance costs include multiple Go modules/protocol generations, separately pinned agent dependencies, SQLite/CGO and MySQL migrations, broker/analytics infrastructure, privileged script admission, RPM/GPG tools and UI replacement/integration. Shallow snapshots and upstream tests do not establish a stable API, support SLA, production security or relative staffing cost. README large-fleet positioning and configured target limits are attributed/configured claims, not measured capacity [S1–S3, R3].

**Reuse as learning:** bounded interfaces between transport and execution; persisted per-target progress; explicit uncertain-delivery classification; repository-specific transactional claims/fences; prepared immutable result identities; staged publication and inventory/signing metadata. Retain the accepted first-party operation Module/native Adapter distinction rather than importing a generic privileged script engine.

**Remaining discriminator:** first obtain a maintainer-linked immutable compatible server/agent release mapping and clarified GPL scope. If adoption is later reconsidered, require a narrowly authorized comparison covering lost native-effect reply, restart/redelivery, stale ownership, cancellation, both SQL backends, mandatory audit/trust and offline management restore. Inventory the actual patches/dependencies and compare against first-party work. None of those tests was authorized or run here; no DataSophon judgment or tracker resolution is made.
